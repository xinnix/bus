# 三秦巴士 P0「买票 → 核销」最小闭环方案

> 修订日期：2026-11-12  
> 适用范围：sqbs 单租户、单品牌小程序、单微信支付商户  
> 目标：用最小范围跑通真实售票与核销，不追求功能对齐现有系统。

---

## 1. P0 一句话定义

**乘客能在小程序查到班次、选上下车点、下单、微信支付、拿到电子票二维码；检票员扫码能核销；管理员能维护线路/班次并查看订单与核销记录。**

这条链路之外的功能，全部后置。

## 3. 用户流程

### 3.1 乘客买票

```
打开小程序 → 微信登录 → 手机号授权
→ 选择线路/日期 → 查看班次列表
→ 选择班次 → 选择上/下车点
→ 填写乘车人/手机号/票数
→ 提交订单（服务端锁库存）
→ 微信支付
→ 支付成功 → 生成电子票（二维码 + 6 位核销码）
→ 我的订单/电子票
```

### 3.2 检票员核销

```
核销员登录 → 选择/确认班次
→ 扫乘客二维码（或输入 6 位核销码）
→ 服务端校验票状态/班次/日期
→ 核销成功（原子更新票状态）
→ 显示乘客姓名/票数/座位/核销时间
→ 重复扫码提示「已于 XX:XX 由 XXX 核销」
```

### 3.3 管理员维护

```
登录后台 → 建线路 → 建上下车点 → 建班次模板
→ 生成未来 7 天班次 → 检查票价/余票
→ 查看订单 → 查看核销记录
```

| `UserIdentity`     | id, userId, appid, openid, unionid                                                                                                                                                   | 微信身份 |

### 4.1 关键约束

- `Order.orderNo` 唯一；`Payment.outTradeNo` 唯一；`Payment.transactionId` 唯一。
- `Ticket.ticketNo` 唯一；`Ticket.checkCode` 唯一。
- `UserIdentity(appid, openid)` 唯一。
- `Order(userId, createdAt)`、`Order(contactPhone)`、`Order(tripId)` 索引。
- `Trip(lineId, serviceDate, status)` 索引。
- 金额全部用 `Int`（分）。
- 订单状态：`PENDING_PAYMENT → PAID → COMPLETED`；超时 → `CLOSED`。
- 票状态：`UNUSED → CHECKED_IN`。
- 班次状态：`ON_SALE → STOPPED/DEPARTED → COMPLETED`。

## 5. 技术方案（P0 专用）

### 5.1 技术栈

- 后端：loom 的 NestJS + tRPC（管理端）+ REST（小程序）+ Prisma + PostgreSQL + Redis。
- 管理端：React 19 + Refine + Ant Design 6。
- 小程序：uni-app + Vue 3；P0 只编译 1 个品牌。
- 支付：微信支付 V3 JSAPI，单个商户号。
- 二维码：服务端签名 token，内容为 `ticketId.expire.signature`，不暴露自增 ID。

### 5.2 关键接口

**管理端 tRPC**：

- `line.list/create/update`
- `station.list/create/update`
- `template.list/create/update`
- `trip.generate/list/update`
- `order.list/getById`
- `checkin.list`
- `checker.list/create/update`

**小程序 REST**：

- `POST /api/v1/auth/wechat/login`
- `POST /api/v1/auth/wechat/phone`
- `GET /api/v1/lines`
- `GET /api/v1/lines/:id/trips?date=YYYY-MM-DD`
- `GET /api/v1/trips/:id`
- `POST /api/v1/orders`（`Idempotency-Key`）
- `POST /api/v1/payments/wechat/prepay`
- `POST /api/v1/payments/wechat/notify`（公开回调）
- `GET /api/v1/orders`
- `GET /api/v1/orders/:id`

**核销端 REST**：

- `POST /api/v1/checker/login`
- `POST /api/v1/checker/verify`
- `GET /api/v1/checker/records`

### 5.3 库存与并发

- 下单时执行原子 SQL：`UPDATE trip SET sold = sold + n WHERE id = ? AND sold + n <= totalSeats`，影响行数为 0 则库存不足。
- 同一订单的票在同一事务内创建。
- 支付回调按 `transactionId` 幂等；重复回调直接返回成功。
- 订单超时任务每分钟扫描 `PENDING_PAYMENT` 且 `expiredAt < now()` 的订单，关闭并释放库存。

### 5.4 电子票核销

- 二维码 token 使用 HMAC-SHA256 签名，包含 `ticketId`、`tripId`、`expireAt`。
- 核销接口用 `UPDATE ticket SET status='CHECKED_IN', checkedAt=now(), checkedBy=? WHERE id=? AND status='UNUSED'`，影响行数为 0 则返回重复/无效。
- 核销记录与票状态在同一事务内写入。

### 11.2 实现要点落点

- 电子票二维码 token：HMAC-SHA256 over `ticketId.tripId.expireAt`，密钥 `TICKET_TOKEN_SECRET`（退回 `JWT_SECRET`）；过期时刻 = 发车时间 + 12h；核销时校验签名与过期。
- 订单超时任务：每分钟关闭 `PENDING_PAYMENT` 且过 `expiresAt` 的订单（条件更新防并发），释放库存、作废票；已有 PAID 支付流水的订单跳过不关闭。
- 竞态兜底：回调晚于关闭时，支付流水照常落库（幂等），订单保持 CLOSED，日志报错并返回 `orderClosed: true`（微信侧收到成功不重投）；退款走 P0.5。
- 核销防重复：`UPDATE ... WHERE status='UNUSED'` 原子更新 + `checkIn.ticketId` 唯一约束，同一事务；重复扫码返回 `ALREADY_CHECKED_IN` + 首次核销时间与操作员。
- 管理端 CRUD：复用 `createCrudRouter`，审计字段（createdById/updatedById）按 `Prisma.dmmf.datamodel` 探测按需注入（Prisma 7 无 `_dmmf`，且票务模型无审计列——盲注会 500，由 E2E 发现后修复）。
