# 三秦巴士 PRD

> 范围与验收以本文为准；实施计划见 [P0-买票核销最小闭环方案](../P0-买票核销最小闭环方案.md)，整体规划见 [三秦巴士-系统重建方案](../三秦巴士-系统重建方案.md)。本文由 loom 脚手架模板 PRD 重写而来（2026-11-12），章节骨架保留。

## 范围边界

### In（P0 最小闭环）

- 单管理员后台：线路 / 上下车点 / 班次模板 / 班次（生成与停售）/ 订单 / 核销记录 / 核销员管理
- 乘客小程序（微信）：微信登录 + 手机号授权、线路/班次查询、选站下单、微信支付（JSAPI）、我的订单、电子票（二维码 + 6 位核销码）
- 核销端（小程序内角色页）：核销员登录、扫码/核销码核销、核销记录
- 订单超时自动关闭释放库存（15 分钟）、下单幂等（Idempotency-Key）、支付回调幂等
- 单品牌小程序、单微信支付商户、单租户

### In（P0.5 运营安全阀，2026-11-14 交付）

- 乘客自助退票（按票、按时间阶梯手续费）与管理端整单退款（已支付订单取消 / 关闭订单异常处理）
- 乘客自助改签（每单一次、同价或低价方向、差价自动原路退回）与管理端整单改签
- 简单日报表（按支付完成日聚合订单数/票数/支付金额 + 退款金额 + 净额）
- 微信订阅消息（出票通知 + 发车前 30 分钟提醒，best-effort）

### Out（明确后置）

| 后置项                                                                                          | 阶段  |
| ----------------------------------------------------------------------------------------------- | ----- |
| 电话预订、快捷登票、优惠券/积分/月卡/分销、多品牌/多商户                                        | P1    |
| 车辆/司机/座位图、包车/旅游/通勤/合同报备、旧系统数据迁移                                       | P1/P2 |
| RBAC 细粒度权限（P0 单管理员 + 核销员）                                                         | P1    |
| 短信通道（需服务商账号）、改签补差价支付流、按线路差异化退改规则、结算单/微信账单对账、报表导出 | P1    |

底座能力（认证、RBAC、文件存储、LLM 抽象层、变更日志）沿用 loom 脚手架，不在本 PRD 重复定义。

## 功能规格

### F1 线路与站点管理（Admin）

线路（名称、出发地、到达地、发布状态、排序）与上下车点（名称、地址、经纬度、排序、状态）；线路-站点按 BOARD/ALIGHT 类型挂接。

**验收**：管理员可完成「建线路 → 建站点 → 挂接上下车站」闭环；未发布线路不出现在小程序。

### F2 班次模板与班次生成（Admin）

班次模板（线路、发车时间、票价、总票数、星期几、状态）+ 按模板批量生成未来 N 天班次（按 weekdays 匹配、按 (线路,日期,发车时间) 幂等去重）；班次支持修改票价/停售。

**验收**：模板生成 7 天班次无重复；停售班次小程序不可见、不可下单。

### F3 乘客下单与支付（小程序）

微信静默登录 + 手机号授权 → 线路/班次查询（按日期余票）→ 选上下车站 → 填写乘车人（1–4 张）→ 提交订单（服务端原子锁库存）→ 微信 JSAPI 支付 → 出票。班次停售规则：发车时间已过 30 分钟停止售票（班次列表标「已停售」且不可选，下单接口硬校验）。

**验收**：同一 Idempotency-Key 重复提交只生成一单；余票不足返回明确错误；50 并发抢 5 座不超卖（集成测试覆盖）；金额单位为分且与微信支付金额一致；发车超 30 分钟的班次下单被拒。

### F4 订单超时与支付回调

15 分钟未支付自动关闭并释放库存；支付回调按 transactionId 幂等、按订单金额校验、留存原始报文。

**验收**：超时订单关闭、票作废、库存回落；回调重投不重复出票；「回调晚于关闭」竞态时支付流水留痕且不重开订单（退款走 P0.5）。

### F5 电子票与核销（小程序 + 核销端）

电子票 = HMAC 签名二维码 token（含过期时间，发车后 12 小时可补扫）+ 6 位核销码；核销端手机号+密码登录，扫码或输码核销，原子更新防重复，重复核销返回首次核销时间与操作员；核销接口仅接受核销员身份 JWT。

**验收**：一张票只能核销一次（并发下亦然）；乘客 JWT 访问核销接口被拒；核销记录可按核销员/班次/日期查询。

### F6 我的订单（小程序）

按状态筛选（全部/待支付/待出行/已完成）；待支付订单可再次发起支付；详情展示电子票。

**验收**：取消支付后可从订单列表/详情重新拉起支付；已关闭订单不可支付。

### F7 退票与改签（P0.5）

**退票**（乘客自助按票 + 管理端整单）：

- 阶梯规则（SSOT `@sanqin/shared`，PRD D6）：发车前 ≥24h 全额退；2h–24h 收 5% 手续费（四舍五入到分）；<2h 不可退。
- 发起后票进入 REFUNDING（不可核销不可再退），微信原路退款；回调成功票转 REFUNDED 并释放库存（发车前），订单聚合为 PARTIALLY_REFUNDED/REFUNDED。
- 改签产生的车票（changedAt 打标）不可退；已核销票不可退。
- 管理端整单退款 = 未核销票全额退（手续费 0），二次确认 + 填写原因；CLOSED 但已支付的订单（超时竞态）全额退支付金额、订单保持 CLOSED，系统自动退款（AUTO_REFUND_ENABLED）。
- 退款单（Refund）记录操作者（USER/ADMIN/SYSTEM）、手续费、原因、网关退款单号；FAILED 可管理端重试（out_refund_no 幂等）与主动对账；每小时兜底对账卡在 PROCESSING 超过 30 分钟的退款单。

**改签**（乘客自助 + 管理端）：

- 规则（PRD D7）：每单仅一次；发车前 2h 内不可改；仅同线路；仅可改到同价或更低价班次（差价自动原路退回），更高价班次拦截提示退票重购；上下车站保留原选择。
- 执行为新班次原子锁库存 → 旧票 CANCELLED + 旧班次释放库存 → 生成新票（changedAt 打标，不可再退/再改）→ 订单随新班次（二维码有效期按新班次发车时刻）→ 写改签单（OrderChange）。
- 无进行中退款时才可改签；改签与新按票退款通过条件更新互斥，并发安全。

**验收**：一张票只能发起一次有效退款（冻结期间重复提交被拒）；并发改签与退款不产生脏数据（条件更新互斥）；退票后库存回落可再售；手续费与到账金额在提交前明示；日报表退款金额与退款流水一致。

### F8 通知与日报表（P0.5）

**微信订阅消息**（短信通道后置 P1）：

- 出票通知：支付成功后 best-effort 发送（模板关键词约定 thing1=线路 / time2=发车时间 / character_string3=订单号）。
- 发车提醒：每 10 分钟扫描 30 分钟内发车班次，按订单聚合发送一次（模板关键词 thing1=线路 / time2=发车时间 / thing3=上车点）；用户未订阅（43101）同样标记已通知。
- 总开关与模板 ID 走平台参数中心（SettingsService `subscribe` 组），未配置一律静默跳过；任何发送失败只记日志，不影响支付/订单主链路。
- 小程序在支付成功后弹订阅授权；车票页提供「发车提醒」入口（`GET /api/subscribe/templates` 下发模板 ID）。

**简单日报表**（Admin `/reports/daily`）：

- 按支付完成日聚合订单数/票数/支付金额；退款金额按退款完成日（仅 SUCCESS）；输出逐日净额与合计；区间 ≤ 92 天。
- 口径与支付流水一致：支付金额含后续发生退款的订单。

**验收**：日报表合计与订单/退款流水核对一致；订阅消息未配置模板时全链路无感降级。
